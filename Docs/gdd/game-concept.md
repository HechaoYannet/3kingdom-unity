# Game Concept: Three Kingdom（三国）

> **Note**: 本文档从现有代码、GDD、ADR、里程碑文档中提炼，经用户审核确认方向。它是项目最高层级的设计参考——所有系统 GDD、ADR、Story 都应与此文档对齐。

---

## 一句话（Elevator Pitch）

> 一款三国题材的策略卡牌对战游戏。玩家扮演三国武将，在回合制规则下用卡牌驱动攻防，通过现代化的 3D 镜头语言和演出效果，让每一次出牌都像一场电影级对决。剧情战斗中引入"剧本模式"——战斗流程可由一套机制和规则有限控制，创造出超越常规对战的震撼视觉与沉浸体验。

---

## 核心身份

| 维度 | 内容 |
|------|------|
| **类型** | 回合制卡牌对战 |
| **题材** | 三国（三国杀启发） |
| **平台** | PC + 移动端 |
| **引擎** | Unity 2022.3 LTS + Tuanjie 1.8.5 |
| **渲染** | URP 14.1.0 |
| **人数** | 单人 vs AI（多人网络为远期目标） |
| **单局时长** | 5–15 分钟 |
| **对标游戏** | 三国杀（规则灵感）、崩坏：星穹铁道（演出与剧本灵感）、Slay the Spire（卡牌策略深度） |

---

## 核心幻想

玩家不是在桌上"挪一张牌"，而是**以武将身份指挥一场风格化对决**。打出"杀"时应感到在命令武将挥刀，触发"闪"时应感到千钧一发的格挡，释放技能时镜头拉近、演出聚焦——**策略化为电影级动作**。

在剧情模式中，战斗流程不再只是标准回合的循环，而是被"剧本"赋予节奏与情感弧线——敌人按设计登场、技能在关键节点触发、镜头在剧情高潮处铺开——玩家的每一次选择都在书写属于自己的三国篇章。

---

## 独特钩子

> 它像三国杀，**同时也**把每一张牌的结算变成 3D 战场上的镜头演出——确定性的规则核心 + 现代化的视觉表达，而不是传统卡牌 UI 的静态桌面。
>
> 更进一步，它的剧情战斗借鉴了崩坏：星穹铁道的设计理念——**战斗可以被"剧本"驱动**。这使它不仅是一款卡牌对战游戏，更是一部玩家参与演出的三国画卷。这是区别于市面普通卡牌游戏的"深刻记忆点"。

---

## 游戏支柱（Game Pillars）

设计支柱是不可妥协的原则。当两个设计决策冲突时，支柱决定取舍。本项目共 5 条支柱。

### 支柱 1：规则权威不可动摇

**一句话**：出牌合法性、目标有效性、伤害/治疗结果、回合顺序——全部由确定性的 Rule Core 裁定，演出层不拥有任何战斗裁决权。

**设计测试**：如果某个视觉效果需要"改一下伤害数字更好看"→ 不行。伤害是规则的，不是演出的。规则计算结果驱动演出，演出不得反向修改规则。

### 支柱 2：每张牌都是演出

**一句话**：基础卡牌走标准演出模板，技能牌享受"英雄时刻"级别的镜头、VFX、音效强化。不存在"只是一张牌"的体验。

**设计测试**：新加一张卡——能否直接套用现有标准模板或英雄时刻模板？如果不能，就是设计或技术债务。

### 支柱 3：一目了然

**一句话**：玩家始终知道谁在出牌、什么阶段、能不能行动、结果如何。HUD、血量、回合提示、目标选择指引——零歧义。

**设计测试**：一个没看过设计文档的测试者能否在 30 秒内读懂屏幕上正在发生什么？不能 → 信息设计不合格。

### 支柱 4：PC/移动双端可降级

**一句话**：高品质效果走 URP + Cinemachine + Timeline。低端设备有明确的回退路径——降 VFX 但不丢信息。

**设计测试**：高端设备的粒子效果在低端跑不动时，是否有保底的 readability 方案（颜色、文字、简化动画）？没有 → 不可上线。

### 支柱 5：剧本模式——战斗即叙事

**一句话**：在剧情战斗中，战斗流程可由一套机制和规则有限控制——敌人的登场时机、关键技能的触发节点、镜头的铺排方式，皆可通过"剧本"编排。这使游戏超越普通卡牌对战，成为玩家参与演出的三国画卷。

**灵感来源**：崩坏：星穹铁道——战斗中嵌入脚本化演出，在特定节点触发超越常规战斗的视觉与情感体验。

**设计测试**：如果一段剧情战斗只是把标准对战加上几句对话 → 不合格。剧本模式必须做到：敌人的登场有节奏、关键技能触发时镜头和 VFX 有变化、战斗的情感弧线被剧本明确设计——而不是交由普通 AI 或回合循环自行演绎。

**优点**：
- 剧情战斗提高玩家印象和留存
- 创造超越常规对战的震撼视觉效果与沉浸感
- 区别于市面普通卡牌游戏的"深刻记忆点"

---

## 反支柱（刻意不做的事）

- **不是动作游戏**：不考验反应速度，核心是策略决策。剧本模式也不引入实时操作。
- **不是开放世界**：游戏空间限定在战斗场景内，不做探索、不做大地图。
- **不是大型多人在线**：当前阶段只做单人 vs AI。多人网络是远期课题，规则核心不做网络假设的过度设计。
- **不让 AI 裁决战斗**：AI 用于加速内容生产（概念图、文档、测试用例），不参与运行时的战斗计算、卡牌合法性、伤害结果。
- **剧本模式不是失控的叙事**：剧本是"受控的战斗流程编排"，不是放弃规则权威。剧本中的每一步战斗结算仍然走 Rule Core。

## 玩家体验分析（MDA 框架）

### 目标美学（玩家感受什么）

| 美学 | 优先级 | 实现方式 |
|------|--------|---------|
| **Fantasy（角色扮演）** | 1 | 扮演三国武将，独特技能与阵营身份 |
| **Challenge（策略挑战）** | 2 | 回合制卡牌决策，目标选择与资源管理 |
| **Narrative（叙事）** | 3 | 剧本模式赋予战斗情感弧线和剧情驱动 |
| **Sensation（感官愉悦）** | 4 | 3D 镜头、VFX、音效、英雄时刻演出 |
| **Discovery（探索发现）** | 5 | 不同武将组合、技能协同的策略探索 |
| **Fellowship（社交）** | N/A | 当前单人阶段不涉及 |
| **Expression（表达）** | N/A | 当前不涉及 |
| **Submission（放松）** | N/A | 不是休闲游戏 |

### 核心机制

1. 回合制卡牌对战：杀/闪/桃 + 武将技能，确定性的规则裁决
2. 剧本驱动战斗：战斗流程可由预设剧本控制，影响敌人登场、技能触发、镜头编排
3. 3D 战斗演出：Cinemachine 镜头 + Timeline 英雄时刻 + VFX/音效反馈
4. AI 内容加速：AI 辅助概念图、文档、测试，不参与运行时裁决

## 玩家动机画像

基于自我决定理论（SDT）的 PENS 模型：

| 需求 | 满足方式 | 强度 |
|------|---------|------|
| **自主性** | 选哪张牌、打谁、什么时候用技能——玩家说了算 | 核心 |
| **胜任感** | 策略战胜 AI、掌握每个武将的独特打法、在剧本战斗中达成关键目标 | 核心 |
| **关联性** | 三国 IP 自带文化认同；剧本模式提供情感投入的连接点 | 辅助 |

### Bartle 玩家类型

- **Achievers（成就者）**：武将收集、剧本通关、策略掌握
- **Explorers（探索者）**：不同武将组合的策略空间探索
- **Killers/Competitors（竞争者）**：远期 PvP 方向

---

## 核心循环

| 层级 | 内容 |
|------|------|
| **瞬间（30秒）** | 查看手牌 → 选牌 → 选目标 → 看演出结算 |
| **短期（5-15分钟）** | 一局完整对决：出牌、响应、技能、胜负 |
| **单次（30-60分钟）** | 若干局对战 + 一段剧情剧本战斗 |
| **长期** | 新武将解锁、剧本章节推进、策略深度积累 |

### 留存钩子

- **好奇心**：下一章剧本故事是什么？下一个武将有什么独特技能？
- **投入感**：已解锁的武将阵容、正在进行的剧本章节
- **掌控感**：策略水平提升、剧本关键节点的精准把握

## MVP 定义

**核心假设**：玩家会觉得"用 3D 演出来表达卡牌对战 + 剧本驱动的剧情战斗"比传统桌面卡牌 UI 更有沉浸感。

**MVP 必须包含**：
1. 1 个正式战斗场景
2. 2 个可操作武将角色（各含 1 个招牌技能）
3. 3 张基础卡牌（杀/闪/桃）可用 + 完整演出模板
4. 1 个标准动作演出模板（可复用）+ 1 个英雄时刻模板（可复用）
5. 1 个完整 PvE 回合流程（出牌 → 响应 → 结算 → 胜负）
6. 1 段最小剧本战斗（验证"剧本模式"概念可在规则框架内实现）

**MVP 明确不做**：
- 全武将阵容扩充
- 网络对战
- 完整进度/养成系统
- 全部剧本章节
- 所有卡牌类型的完全实现

### 范围层级

| 层级 | 内容规模 | 目标 |
|------|---------|------|
| **MVP** | 2 武将、3 卡牌、1 剧本片段 | 验证核心循环 + 剧本概念 |
| **垂直切片** | 完整 PvE 对决 + 1 完整剧本章节 | 端到端可演示 |
| **Alpha** | 全武将、多章节剧本、完整 UI | 功能齐备 |
| **完整愿景** | 全部内容 + 网络对战 + 全部演出打磨 | 可发行品质 |

## 风险与待解问题

### 设计风险
- 剧本模式的"有限控制"边界不清，可能导致规则权威被侵蚀
- 剧本战斗中的演出与策略决策可能冲突（演出打断思考流）

### 技术风险
- URP 迁移成本可能高于预期
- 剧本系统需要一套新的数据格式和运行时解释器
- 移动端降级后剧本出效果还能否保留"深刻记忆点"

### 待解问题
- [ ] 剧本的数据格式：JSON 驱动还是 Timeline 驱动？还是混合？
- [ ] 剧本中哪些战斗参数可以被覆盖、哪些必须走 Rule Core？
- [ ] 首段验证剧本的选择——哪个三国场景最具代表性？

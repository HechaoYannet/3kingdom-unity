# Game Pillars: Three Kingdom（三国）

---

## 什么是游戏支柱？

支柱是定义本游戏身份的 5 条不可妥协原则。每一个设计、美术、音频、叙事、技术决策都必须服务至少一条支柱。如果一个特性不服务于任何支柱，它就不属于这个游戏。

**好的支柱**：
- **可证伪**：能用一个具体的设计决策来检验
- **有限制力**：能迫使你说"不"
- **跨部门**：对设计、美术、音频、程序都有约束
- **可记忆**：团队能脱口而出

---

## 核心幻想

> 玩家不是在桌上"挪一张牌"，而是**以武将身份指挥一场风格化对决**。策略化为电影级动作。剧情战斗中，战斗流程被"剧本"赋予节奏与情感弧线——玩家的每一次选择都在书写属于自己的三国篇章。

---

## 五大支柱

### 支柱 1：规则权威不可动摇

**定义**：出牌合法性、目标有效性、伤害/治疗结果、回合顺序——全部由确定性的 Rule Core 裁定。演出层不拥有任何战斗裁决权。Rule Core 计算的结果驱动演出，演出不得反向修改规则。

**目标美学**：Challenge（策略挑战）

**设计测试**：如果某个视觉效果需要"改一下伤害数字更好看"→ 不行。伤害是规则的，不是演出的。

**各部门含义**：

| 部门 | 这条支柱说... | 例子 |
|------|-------------|------|
| **游戏设计** | 所有卡牌效果必须先定义为规则结果，再配演出 | 新卡牌先写 Rule Result Schema，再写演出模板 |
| **美术** | 演出不可为了好看而加一个不存在于规则里的伤害 | VFX 的冲击力不能暗示规则之外的数值 |
| **音频** | 音效反馈必须与规则结果一一对应 | 命中/未命中/暴击各有明确音效，不凭空出现"大伤害感" |
| **程序** | Rule Core 层零依赖演出层；演出层只能读规则结果 | 不存在 `PresentationManager` 在 `CardResolver` 里的引用 |

**符合此支柱的决策**：
- 伤害值由 `RuleCore` 计算，演出层只读不写
- 卡牌合法性校验在规则层完成，演出层收到的是"已确认合法"的结果

**违反此支柱的行为**：
- 因为某个 VFX 太炫酷而临时加一段额外伤害
- 演出脚本直接修改战斗数值

---

### 支柱 2：每张牌都是演出

**定义**：基础卡牌（杀/闪/桃）走标准动作演出模板；技能牌享受"英雄时刻"级别的镜头、VFX、音效强化。不存在"只是一张牌"的体验。模板必须是可复用的——新卡牌加入应优先套用现有模板。

**目标美学**：Sensation（感官愉悦）、Fantasy（角色扮演）

**设计测试**：新加一张卡——能否直接套用现有标准模板或英雄时刻模板？如果不能 → 设计或技术债务。

**各部门含义**：

| 部门 | 这条支柱说... | 例子 |
|------|-------------|------|
| **游戏设计** | 设计卡牌效果时同步定义其演出层级（标准/英雄） | 每张新卡的设计文档必须包含 Presentation Tier |
| **美术** | 标准模板有统一的 VFX 语言；英雄时刻允许突破 | 标准攻击 = 统一镜头 + 统一 VFX 位置；英雄技能 = 定制镜头轨道 |
| **音频** | 标准模板有统一音效预设；英雄时刻有专属配乐片段 | 标准攻击音效库 vs. 吕布无双专属 BGM |
| **程序** | 模板系统支持参数化配置，不因新卡牌而硬编码 | 演出定义走数据驱动（JSON/SO），不走 switch-case |

**符合此支柱的决策**：
- 杀和闪共享同一个"攻击→格挡"的双人演出模板
- 黄盖的苦肉技能走英雄时刻模板，定制镜头 + 专属 VFX

**违反此支柱的行为**：
- 每张新卡都写一套独特的演出代码
- 基础卡牌没有演出，只是 UI 上飘一个数字

---

### 支柱 3：一目了然

**定义**：玩家始终知道——谁在出牌、什么阶段、能不能行动、结果如何。HUD、血量、回合提示、目标选择指引——零歧义。信息设计的目标是：一个路人看 30 秒屏幕就能理解战况。

**目标美学**：Challenge（清晰反馈是策略决策的前提）

**设计测试**：一个没看过设计文档的测试者能否在 30 秒内读懂屏幕上正在发生什么？

**各部门含义**：

| 部门 | 这条支柱说... | 例子 |
|------|-------------|------|
| **游戏设计** | 每个交互必须有明确的 affordance | 可出的牌高亮、不可出的牌压暗、目标按钮有文字说明 |
| **美术** | 信息层级优先于装饰层级 | HP 条在视觉上比背景粒子更突出 |
| **音频** | 关键状态变化有辨识度高的音效 | 回合切换音效、响应提示音效 |
| **程序** | UI 更新频率不低于每帧一次，不依赖轮询延迟 | 回合状态变化立即刷新 HUD |

**符合此支柱的决策**：
- 顶部居中显示当前阶段名称 + 当前行动方
- 可出牌阶段高亮手牌中可用的卡
- 响应窗口有倒计时 + 明确提示

**违反此支柱的行为**：
- 血量变化只有 Log 没有 UI
- 目标选择没有指引，玩家不知道"先点杀再选目标"

---

### 支柱 4：PC/移动双端可降级

**定义**：高品质效果走 URP + Cinemachine + Timeline。低端设备有明确的回退路径——降 VFX 但不丢失信息。Readability 是底线，不是奢侈。

**目标美学**：Sensation（感官愉悦在能力范围内最大化）

**设计测试**：高端设备的粒子效果在低端跑不动时，是否有保底的 readability 方案（颜色变化、简化动画、文字反馈）？

**各部门含义**：

| 部门 | 这条支柱说... | 例子 |
|------|-------------|------|
| **游戏设计** | 关键信息不依赖高端效果传达 | 伤害结果同时用数字 + 血条动画 + 文字，不只用粒子 |
| **美术** | 每个效果有 High/Low 两套预设 | 英雄时刻 VFX → 低端回退到简化版或颜色变化 |
| **音频** | 音频不降级，始终完整 | 音频是轻量资源，不做降级 |
| **程序** | 运行时检测设备能力并自动选择效果层级 | 启动时跑一次 GPU benchmark，设定 Quality Tier |

**符合此支柱的决策**：
- 伤害反馈 = 数字飘字（必达）+ 血条扣减动画（必达）+ 粒子冲击（可选）
- 英雄时刻在低端设备上减少后处理、降低粒子密度，但保留镜头运动和关键帧

**违反此支柱的行为**：
- 低端设备上关键战斗信息消失（因为只有粒子表示）
- 只有一个"Ultra"画质档位

---

### 支柱 5：剧本模式——战斗即叙事

**定义**：在剧情战斗中，战斗流程可由一套机制和规则有限控制——敌人的登场时机、关键技能的触发节点、镜头的铺排方式，皆可通过"剧本"编排。剧本不是放弃规则权威，而是在规则框架之上增加一层"导演层"，让战斗成为玩家参与演出的三国画卷。

**灵感来源**：崩坏：星穹铁道——战斗中嵌入脚本化演出，在特定节点触发超越常规战斗的视觉与情感体验。

**目标美学**：Narrative（叙事）、Fantasy（角色扮演）、Sensation（感官愉悦）

**设计测试**：
- 一段剧情战斗如果只是把标准对战加上几句对话 → 不合格。
- 剧本模式必须做到：敌人登场有节奏、关键技能触发时镜头和 VFX 有变化、战斗的情感弧线被剧本明确设计。
- 反过来说——剧本中的每一步战斗结算仍然走 Rule Core，不能因为"剧情需要"而跳过规则校验。

**优点**：
- 剧情战斗提高玩家印象和留存
- 创造超越常规对战的震撼视觉效果与沉浸感
- 区别于市面普通卡牌游戏的"深刻记忆点"

**各部门含义**：

| 部门 | 这条支柱说... | 例子 |
|------|-------------|------|
| **游戏设计** | 剧本定义战斗的"导演层"，不替代规则层 | 剧本说"第三回合敌方增援登场"——规则层正常 add 敌人，演出层加戏剧化入场 |
| **美术** | 剧本节点有专属的视觉语言 | 增援登场 = 特定镜头切入 + 专属 VFX + 角色 pose |
| **音频** | 剧本节点驱动音乐变化 | 增援登场 → BGM 变奏或切换；Boss 残血 → 音乐加强 |
| **叙事** | 剧本是叙事的战斗表达 | 剧情高潮落在剧本战斗的关键节点，而非纯播片 |
| **程序** | 剧本系统是 Rule Core 的上层编排者，通过事件钩子与规则层交互 | 剧本引擎读取剧本数据 → 在指定时机向 Rule Core 注入事件 → Rule Core 正常结算 → 结果驱动演出 |

**符合此支柱的决策**：
- 三英战吕布：剧本定义吕布分阶段使用技能、刘备/关羽/张飞依次登场支援
- 赤壁之战：剧本控制火攻在特定回合触发，改变战场状态
- 每一段剧本的关键节点 = 预设镜头 + 专属 VFX + BGM 变化

**违反此支柱的行为**：
- 剧本模式直接跳过规则校验（"剧情需要所以吕布无敌"）→ 违反支柱 1
- 剧本只是一段不可跳过的播片，没有战斗交互
- 所有剧情战斗和普通对战一模一样

## 支柱冲突解决

当两条支柱冲突时，按以下优先级裁决：

| 优先级 | 支柱 | 理由 |
|--------|------|------|
| 1 | 规则权威不可动摇 | 没有确定性的规则核心，游戏就不存在 |
| 2 | 一目了然 | 玩家看不懂战斗，一切演出都白费 |
| 3 | 每张牌都是演出 | 这是产品的差异化所在 |
| 4 | 剧本模式——战斗即叙事 | 这是深刻的记忆点和剧情载体 |
| 5 | PC/移动双端可降级 | 信息可达是底线，但感官可以妥协 |

**裁决流程**：
1. 识别冲突双方涉及哪两条支柱
2. 对照优先级表
3. 低优先级支柱如果能部分满足而不损害高优先级支柱 → 做
4. 如果不能 → 高优先级支柱胜出
5. 记录决策理由在相关设计文档中

**示例冲突**：
- "剧本模式想让吕布在残血时触发一个狂暴演出，但狂暴期间的伤害加成要不要走规则？"
- → 支柱 1 优先于支柱 5。狂暴的伤害加成必须由规则层计算（可定义"狂暴 = ATK * 1.5"作为规则效果），剧本层只负责在规则触发狂暴时配上演出。

## 反支柱（刻意不做的事）

- **不是动作游戏**：不考验反应速度，核心是策略决策。剧本模式不引入实时操作。
- **不是开放世界**：游戏空间限定在战斗场景内，不做探索、不做大地图。
- **不是大型多人在线**：当前阶段只做单人 vs AI。多人网络是远期课题，规则核心不做网络假设的过度设计。
- **不让 AI 裁决战斗**：AI 用于生产加速，不参与运行时的战斗计算。
- **剧本模式不是失控的叙事**：不因"剧情需要"而跳过规则校验。

## 玩家动机对齐

基于自我决定理论（SDT）：

| 需求 | 服务支柱 | 如何实现 |
|------|---------|---------|
| **自主性**（选择自由） | 支柱 1、支柱 5 | 规则保证了可选的策略空间；剧本提供情境但不限制玩家决策 |
| **胜任感**（掌握与成长） | 支柱 1、支柱 3 | 清晰的规则反馈让玩家理解自己的策略是否正确 |
| **关联性**（情感连接） | 支柱 5、支柱 2 | 剧本模式提供对武将和故事的情感投入；演出强化代入感 |
